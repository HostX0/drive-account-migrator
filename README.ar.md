# نقل Google Drive بين حسابين

أداة محلية تنسخ ملفاتك من حساب Google إلى حساب ثاني، مع **خيار إعطاء الحساب القديم صلاحية Editor أو عدم إضافة صلاحية له**. بيها واجهة بالمتصفح وشرح للربط، والنقل يشتغل بسكربت Python بدون ذكاء اصطناعي لكل ملف.

[English](README.md) · [شرح الربط بالتفصيل](docs/setup.md) · [الاستئناف والحماية](docs/safety.md)

## شلون أشغلها؟

نزّل Python من [الموقع الرسمي](https://www.python.org/downloads/)، نسخة 3.10 أو أحدث، ونزّل المشروع من GitHub: **Code → Download ZIP**. فك الضغط وافتح مجلد المشروع.

على Windows افتح **Start Windows.bat**. على macOS افتح **Start macOS.command**. إذا ما اشتغل الملف مباشرة، افتح Terminal داخل مجلد المشروع وشغّل:

```sh
python3 -m drive_migrator gui
```

على Windows تقدر تستخدم:

```powershell
py -3 -m drive_migrator gui
```

تفتح واجهة على جهازك بعنوان `127.0.0.1`. خلي نافذة الطرفية مفتوحة أثناء العمل. ما تحتاج استضافة، اشتراك بالأداة، أو مفتاح لخدمة ذكاء اصطناعي.

## منين أجيب ملف الربط؟

اللي تحتاجه **ملف OAuth بصيغة JSON**، مو API key عادي. كل شخص يسوي ملفه الخاص؛ لا تنشره ويا المشروع.

1. افتح [Google Cloud Console](https://console.cloud.google.com/) وسوّي مشروع.
2. فعّل **Google Drive API** و**Google Docs API**. لا تفعّل Billing ولا تبدأ تجربة مدفوعة لهذا الإعداد.
3. من Google Auth Platform اختَر External وخلي التطبيق Testing. أضف الإيميلين إلى Test users.
4. من Clients اختَر Create client، ونوعه **Desktop app**، وبعدها نزّل ملف JSON.
5. بواجهة الأداة اضغط **Choose JSON file** واختَر الملف. اكتب الإيميل القديم والجديد، وروابط مجلدي المصدر والوجهة.
6. اضغط ربط الحساب القديم، وبعده الجديد. Google يفتح بالمتصفح؛ تأكد من الإيميل قبل الموافقة. الأداة ما تطلب كلمة مرورك.

شارك مجلد المصدر مع الحساب الجديد بصلاحية Viewer من داخل Drive حتى يقدر ينسخ. سوّي مجلد وجهة بالحساب الجديد **بنفس اسم مجلد المصدر بالضبط**. الحساب الجديد لازم يملك مساحة كافية.

بعد الربط اضغط **Create controller once** مرة واحدة فقط. إذا عندك نقل سابق، حمّل إعداده واستعمل نفس سجل التحكم ونفس مجلد الحالة، ولا تسوي نسخة ثانية جديدة.

## النقل والمشاركة

ابدأ بـ **Build preview** لمراجعة الموجود والناقص. بعدها **Start / resume copy** ينسخ دفعة محدودة. تقدر تكرره حتى تكمل العناصر المؤهلة. الأسماء والمجلدات الفارغة محفوظة، والمجلدات المتشابهة بالاسم ما تندمج عشوائياً.

خيار **Keep the old account connected to your files**:

- مفعّل: يضيف صلاحية Editor للحساب القديم على مجلد الوجهة ويفحص وصوله.
- غير مفعّل: ما يضيف صلاحية جديدة للحساب القديم.

إلغاء الخيار ما يسحب صلاحيات قديمة أو موروثة كانت موجودة من قبل. إذا تريد النسخ خاصة بالحساب الجديد وحده، راجع المشاركة في Drive.

## تفريغ المساحة

النسخ وحده ما يفرغ الحساب القديم. ونقل الملفات للسلة **يبقيها محسوبة على المساحة**.

مرحلة Cleanup منفصلة: تربط الحساب القديم بصلاحية إضافية، تسوي معاينة، وتشوف قائمة الملفات. تكتب عبارة تأكيد قبل تنفيذ الخطة. الحذف النهائي يكون فقط لملفات ثنائية ثبتت نسخها وسابقاً نقلتها الأداة للسلة. **الحذف النهائي ما يرجع.** مؤشر المساحة ممكن يتأخر بعد الحذف الكبير. [تعليمات Google](https://support.google.com/drive/answer/6374270?hl=en).

الأداة ما تمسح كل الحساب بضغطة واحدة، ولا تفرغ السلة كلها. تترك المجلدات، ملفات Google الأصلية مثل Docs وSheets، الملفات المحظورة، والنسخ اللي تغيرت أو ما ثبت تطابقها. Gmail وGoogle Photos خارج نطاقها.

## الخصوصية والاستئناف

التوكنات وملف الربط والتقارير تبقى بمجلد خاص على جهازك خارج المشروع. لا ترفعها إلى GitHub ولا ترسلها ضمن بلاغ مشكلة. احتفظ بمجلد الحالة حتى تقدر تستأنف بدون تكرار النسخ.

إذا انقطع الاتصال بعد نسخة محتملة، الأداة تفحص النتيجة قبل أي إعادة. إذا ظهر منع صلاحية أو نتيجة غير مؤكدة، تتوقف وتحفظ السجل؛ ما تتجاوز قيود Google.

هذه نسخة أولية، وفحص ملفات Google الأصلية يقتصر على البيانات الوصفية المتاحة، لذلك ما تدخل بالحذف التلقائي. راجع التقارير والنسخ المهمة بنفسك قبل أي حذف نهائي. المشروع لا يفعّل الفوترة ولا يشتري مساحة؛ [حدود Google الحالية](https://developers.google.com/workspace/drive/api/guides/limits) تبقى مطبقة.
